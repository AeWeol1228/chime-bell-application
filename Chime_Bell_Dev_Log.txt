[Chime Bell App 개발 일지 - 2026.04.15]

1. 프로젝트 개요
- 기능: 매 정시마다 사용자가 설정한 소리를 재생하는 백그라운드 알람 서비스
- 주요 기술 스택: Flutter, android_alarm_manager_plus, audioplayers, shared_preferences

2. 아키텍처 (Architecture)
- UI Layer: Flutter 기반의 설정 화면 (DND 설정, 주말 제외, 소리 선택 등)
- Service Layer:
  * SettingsService: SharedPreferences를 활용한 사용자 설정 데이터 유지 관리
  * AlarmService: Android 시스템의 AlarmManager와 Dart Isolate를 연결하는 브릿지 역할
- Background Layer: 앱이 종료되거나 백그라운드에 있을 때 실행되는 독립적인 Dart Isolate

3. 워크플로우 (Workflow)
- [설정] 사용자가 앱에서 알람을 활성화함
- [예약] AlarmService가 Android 시스템의 AlarmManager에 정시 알람을 등록
- [트리거] 정시가 되면 Android OS가 앱의 AlarmService(Native)를 호출
- [Isolate 실행] Native 서비스가 새로운 Dart Isolate를 생성하고 main.dart에 정의된 'alarmCallback' 함수를 실행
- [조건 체크] alarmCallback 내에서 현재 시간, DND 모드 활성화 여부, 주말 제외 설정을 체크
- [재생] 모든 조건을 만족하면 오디오 파일을 로드하여 재생

4. 주요 에러 및 해결 과정 (Troubleshooting)

(1) 문제: 백그라운드에서 alarmCallback 함수를 찾지 못함
- 원인: Flutter의 트리셰이킹(Tree Shaking) 과정에서 백그라운드 함수가 제거되거나, Native 영역에서 접근할 수 없는 위치(클래스 내부)에 있었음.
- 해결: alarmCallback을 main.dart의 최상단(Top-level)으로 옮기고, @pragma('vm:entry-point') 어노테이션을 추가하여 Native 영역에서의 가시성을 확보함.

(2) 문제: RebootBroadcastReceiver 관련 PlatformException 발생
- 원인: android_alarm_manager_plus 패키지 버전이 업데이트되면서 네이티브 클래스 패키지 경로가 변경됨 (android_alarm_manager_plus -> androidalarmmanager).
- 해결: AndroidManifest.xml에 등록된 AlarmService, AlarmBroadcastReceiver, RebootBroadcastReceiver의 android:name 경로를 실제 플러그인 구조에 맞게 수정함.

(3) 문제: Attempted to start a duplicate background isolate 경고
- 원인: 앱이 포그라운드에 있는 상태에서 알람이 울릴 경우, 이미 초기화된 AndroidAlarmManager를 다시 초기화하려고 시도하면서 충돌 발생.
- 해결: AlarmService 클래스 내부에 _initialized 플래그를 도입하여, 이미 초기화된 경우 initialize() 호출을 건너뛰도록 방어 로직을 구현함.

5. 현재 상태
- 앱이 켜져 있거나 완전히 종료된 상태(Cold Boot) 모두에서 정시 알람이 정상적으로 작동함을 확인 완료.
- 정시 알람 예약 및 1분 테스트 알람 기능 정상 작동.

[Chime Bell App 개발 일지 - 2026.04.18 (추가)]

1. 정시 알람 지연 문제 해결 (Hourly Chime Delay Fix)
- 현상: 정시 알람이 정시가 아닌 6~8분 뒤에 불규칙하게 울리는 현상 발생.
- 원인 분석: 
  * 상세 로깅 시스템(`execution_log.txt`)을 구축하여 분석한 결과, 앱 예약 로직은 정확했으나 Android OS가 `periodic` 알람을 배터리 최적화를 위해 강제로 미루는(Batching) 것을 확인.
  * 최신 안드로이드 버전에서 주기적 알람(`periodic`)은 `exact: true` 옵션을 주더라도 시스템에 의해 실행 윈도우가 임의로 조정될 수 있음.

2. 해결 방법: 일회성 체인 예약 방식 (One-Shot Chain Reservation)
- 기존: `AndroidAlarmManager.periodic`을 사용하여 시스템에 반복 예약을 맡김.
- 변경:
  * `AlarmService.scheduleChime()`에서 `oneShotAt`을 사용하여 오직 **다음 정각 한 번**만 예약.
  * `BackgroundService.alarmCallback()`이 실행될 때마다 즉시 **다음 정시 알람을 새로 예약**하여 연쇄적으로 동작하도록 구현.
- 효과: 시스템이 이를 '반복 작업'으로 인지하여 미루는 것을 방지하고, 매번 새로운 고우선순위 알람으로 인식하게 하여 정시 실행 정밀도를 극적으로 향상시킴 (오차 범위 1초 이내 확인).

3. 진단 도구 강화
- 상세 워크플로우 로깅: 예약 시점(`[SCHEDULER]`)과 실제 실행 시점(`>>> [EXECUTOR]`)을 모두 기록하여 지연 발생 시 주체를 명확히 판별할 수 있도록 개선.
- 개발자 메뉴 고도화: 앱 내에서 바로 실행 로그를 확인(`View Log`)하고 관리(`Clear Log`)할 수 있는 UI 추가.

[Chime Bell App 개발 일지 - 2026.04.19]

1. 오디오 덕킹 및 미디어 정지 문제 해결 (Audio Ducking & Focus Fix)
- 현상: 정시 알람이 울릴 때 유튜브 등 미디어 재생이 일시 정지되거나, 알람 종료 후 미디어 볼륨이 복구되지 않는 현상 발생.
- 원인 분석: 
  * 오디오 포커스 설정이 `media` 채널로 되어 있어 기존 재생 중인 미디어와 경쟁 관계 형성.
  * 소리 재생 후 플레이어 리소스 및 오디오 포커스를 명시적으로 해제(`dispose`)하지 않아 시스템이 복구 시점을 인지하지 못함.
- 해결 방법:
  * `AndroidUsageType.alarm` 및 `AndroidAudioFocus.gainTransientMayDuck` 조합 사용: Doze 모드에서의 높은 우선순위를 유지하면서도 타 앱의 미디어를 정지시키지 않고 볼륨만 낮추도록 설정.
  * 재생 완료 후 `player.dispose()` 호출: 알람 소리가 끝나는 즉시 오디오 포커스를 반환하여 유튜브 등 타 앱의 볼륨이 즉시 원래대로 돌아오도록 개선.

2. 주요 버그 수정 (Critical Bug Fix)
- 현상: 개발자 설정에서 '디버그 로그'를 끌 경우 알람 자체가 실행되지 않고 다음 알람 예약도 중단되는 문제 발견.
- 원인: `BackgroundService.alarmCallback` 내부에 로깅 활성화 여부를 체크하는 `if`문이 알람 예약 로직보다 상단에 위치하여 조기 리턴(Early Return) 발생.
- 해결: 로깅 설정과 관계없이 알람 실행 및 다음 시간 예약이 항상 수행되도록 로직 순서 재배치.

3. 기타 개선 사항
- 빌드 시스템 복구: `build.ps1` 스크립트를 통한 빌드 시간(`build_info.dart`) 자동 갱신 프로세스 재확립 및 배포 확인.
- UI 동기화: 설정 화면의 미리보기 기능에도 백그라운드 서비스와 동일한 오디오 컨텍스트를 적용하여 일관된 동작 보장.

4. 결과 확인
- 유튜브 재생 중 알람 발생 시: 유튜브 소리 일시 감소 -> 알람 소리 출력 -> 알람 종료 즉시 유튜브 볼륨 복구 확인 완료.
- 릴리즈 모드 배포 및 실기기(SM A908N) 정상 동작 확인.
